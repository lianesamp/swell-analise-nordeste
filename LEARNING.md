## Climate / Ocean Data

| Term | Explanation |
|------|-------------|
| **ERA5** | A global climate reanalysis dataset produced by ECMWF (European Centre for Medium-Range Weather Forecasts). It reconstructs past weather by combining historical observations with numerical models. Covers 1979–present, hourly resolution. Think of it as a "simulation of the past" that fills gaps where no instruments existed. |
| **Reanalysis** | A method that re-runs a weather model over past decades using all available observations (satellites, buoys, weather stations). The result is a consistent, gap-free dataset — unlike raw observations which have missing data and uneven coverage. |
| **WaveWatch III (WW3)** | A wave model developed by NOAA/NCEP. It simulates how ocean waves are generated by wind, propagate across the ocean, and arrive at coastlines. The NOAA version provides global wave forecasts and hindcasts. |
| **ERDDAP** | A data server developed by NOAA that provides scientific datasets in multiple formats (CSV, NetCDF, JSON). You query it via URL parameters — similar to a REST API for climate data. The WW3 data was accessed through ERDDAP at `erddap.aoml.noaa.gov`. |
| **CDS (Climate Data Store)** | The data portal run by Copernicus/ECMWF where ERA5 is distributed. You register, get an API key, and use the `cdsapi` Python library to download data programmatically. |
| **NetCDF (.nc)** | A binary file format standard for scientific array data — especially climate/ocean data. Stores multidimensional arrays (e.g., height × time × lat × lon) with metadata. Opened in Python with `xarray` or `netCDF4`. Similar concept to a structured database but optimized for large numerical grids. |
| **Swell** | Ocean waves that have traveled far from the storm that generated them. They are more organized and have longer periods than local wind waves. For surfing, swell is what matters — it carries energy over thousands of kilometers. |
| **Significant wave height (Hs)** | The average height of the highest one-third of waves. It's the standard metric for wave height in oceanography. Not the maximum wave — roughly what an experienced observer would estimate as "the wave height." |
| **Peak period (Tp)** | The wave period (seconds between consecutive crests) with the most energy. Longer periods = more energy = waves that travel farther and break more powerfully. WW3's `sper` is a peak period. |
| **Mean period (Tm)** | The average period across all wave frequencies in the spectrum. Always lower than peak period — typically by 3–4 seconds for swell. ERA5's `mpts` is a mean period. This is a critical difference: you cannot directly compare ERA5 mean period with WW3 peak period. |
| **Wave direction (FROM)** | Convention used by both ERA5 and WW3: the direction the waves are coming FROM, in degrees. 0° = from the North, 90° = from the East. A "NE swell" at 45° means the swell is arriving from the northeast heading toward the southwest. |
| **Offshore point** | A coordinate in the open ocean used as reference for wave analysis. Our point (-3.5°, -38.5°) is offshore of Ceará. Wave conditions there are NOT the same as at the beach — waves transform as they approach shore (refraction, shoaling, breaking). |

## Python / Data Libraries

| Term | Explanation |
|------|-------------|
| **xarray** | A Python library for working with labeled multidimensional arrays. It's like pandas but for N-dimensional data — perfect for climate datasets that have dimensions like time, latitude, longitude. Used to read NetCDF files. |
| **netCDF4** | A lower-level Python library for reading/writing NetCDF files. `xarray` uses it internally as an "engine" (`engine='netcdf4'`). You rarely use it directly — `xarray` provides a friendlier API. |
| **cdsapi** | The official Python client for the Copernicus Climate Data Store. After configuring your API key, you use `cdsapi.Client().retrieve(...)` to request and download ERA5 data. It handles authentication and queuing. |
| **PapaParse** | A JavaScript CSV parser used in the React frontend. It reads CSV files in the browser and returns parsed data as objects. Similar to how `pandas.read_csv()` works in Python, but for the client side. |

## Statistics

| Term | Explanation |
|------|-------------|
| **Wilson confidence interval** | A method for calculating confidence intervals for proportions (e.g., "X out of Y years had an event"). Better than the naive formula (p ± z√(p(1-p)/n)) when sample sizes are small or proportions are near 0 or 1. Used here because we have 47 years — not huge, not tiny. |
| **McNemar test** | A statistical test for comparing two related (paired) binary outcomes. We use it to compare week 3 vs week 4 because the same years are measured in both weeks — they're paired. It answers: "Is there a significant difference in event occurrence between the two weeks?" |
| **Spearman correlation** | A rank-based correlation that measures monotonic relationships — does Y tend to increase when X increases? Used for trend analysis instead of Pearson because it doesn't assume linear relationships and is robust to outliers. |
| **Circular statistics** | Special methods for handling angular data (like wind/wave direction in degrees). You can't simply average 350° and 10° as (350+10)/2 = 180° — that's wrong. Circular mean uses sine/cosine to get the correct answer: ~0°. |
| **Pseudo-replication** | A statistical error where you treat dependent observations as independent. Example: counting 24 consecutive hours of the same swell as 24 separate "events" inflates your sample size and gives falsely confident results. That's why we group consecutive hours into single events. |
| **Percentile (P50, P75, P90, P95)** | The value below which a given percentage of observations fall. P90 = 90% of values are below this. More informative than a fixed threshold (like "Hs >= 1.5m") because it tells you how a specific swell compares to the historical distribution. |

## Project-Specific Concepts

| Term | Explanation |
|------|-------------|
| **Event** | A continuous period where swell conditions meet specific criteria (direction + period + height). Hours are grouped: if conditions are met from 08:00 to 15:00, that's one event of 8 hours — not 8 events. A 1-hour gap tolerance prevents artificial splitting. |
| **Scenario levels** | Different combinations of thresholds used to classify swell intensity. From "any relevant" (loose) to "exceptional" (strict). Each scenario answers a different question: "Will there be ANY swell?" vs "Will there be GREAT swell?" |
| **Surfable window** | A continuous block of time with favorable conditions. Important for trip planning: a single hour of swell has less practical value than 12 hours. We calculate the probability of windows ≥3h, ≥6h, ≥12h, ≥24h. |
| **ERA5 vs WW3 threshold calibration** | Because ERA5 uses mean period (~3-4s lower than peak period), the thresholds must be different. WW3 "period ≥ 12s" is roughly equivalent to ERA5 "period ≥ 9s". This calibration was derived by comparing the distributions of both datasets. |

## React Patterns

| Term | Explanation |
|------|-------------|
| **Custom Hook** | A reusable function starting with `use` that encapsulates stateful logic. Similar to Vue composables (`useFetch`, `useCounter`) or Laravel Service classes. Example: `useCearaData()` loads 3 CSVs once and shares the parsed data across all components that call it — avoiding duplicate fetches. |
| **useMemo** | A React hook that caches (memoizes) a computed value and only recalculates when its dependencies change. Like Vue's `computed()`. Use it when you transform raw data into display-ready data — prevents re-processing on every render. |
| **Controlled Component** | A form input (select, input, checkbox) where React state is the single source of truth. The input displays the state value, and `onChange` updates it. Similar to `v-model` in Vue: `<select value={x} onChange={e => setX(e.target.value)}>`. |
| **Module-level cache** | A variable declared outside any component that persists across renders and component instances. Unlike `useState` (per-component), a module-level variable is shared by all components that import the same module. Used in `useCearaData` to avoid re-fetching CSVs. |
| **Smooth scrolling** | CSS `scroll-behavior: smooth` makes anchor link navigation (`#section`) scroll smoothly instead of jumping. One line of CSS that improves UX significantly. |

## Python — Validation & CLI

| Term | Explanation |
|------|-------------|
| **Pydantic** | A data-validation library that uses Python type hints to validate data at runtime. You declare a model with types and constraints (like `lat: float = Field(ge=-90, le=90)`), and Pydantic guarantees the data matches — or raises a clear error. It's the Python equivalent of Zod in TypeScript. |
| **BaseModel** | The base class from Pydantic. You inherit from it to create a validated data model. Fields are declared as class attributes with type annotations. When you instantiate it (`GeoPoint(lat=5, lon=10)`), Pydantic validates all fields automatically. |
| **Field()** | Pydantic function for adding constraints to a model field: `Field(ge=0, le=90)` means "greater or equal 0, less or equal 90". Similar to Laravel's validation rules like `'lat' => 'numeric|between:-90,90'`. |
| **field_validator** | A Pydantic decorator for custom validation on a single field. Use it when built-in constraints aren't enough (e.g., validating that angle ranges are within 0–360). Similar to Zod's `.refine()` or Laravel's custom Rule objects. |
| **model_validator** | A Pydantic decorator for validation that depends on multiple fields (e.g., `end_year >= start_year`). Runs after all individual fields are validated. No equivalent in Zod — you'd use `.refine()` on the whole schema. |
| **Typer** | A CLI framework that builds command-line interfaces from Python function signatures. You write a function with typed parameters, and Typer auto-generates `--help` text, argument parsing, and validation. Think of it as Laravel's Artisan commands, but auto-generated from type hints. |
| **typer.Option()** | Declares a CLI option (flag) with metadata: default value, short alias, help text, and constraints. `typer.Option(1, "--from-step", "-f", min=1, max=7)` creates `--from-step` / `-f` that only accepts 1–7. |
| **Rich** | A Python library for styled terminal output: colored text, tables, progress bars, panels. Comes bundled with Typer. Replaces plain `print()` with formatted, readable output. `Console().print("[bold red]Error[/]")` prints bold red text. |
| **Rich Table** | A Rich class that renders formatted ASCII/Unicode tables in the terminal. You add columns, then rows, and Rich handles alignment, borders, and styling. Similar to `php artisan` command output tables. |
| **Lazy import** | Importing a module inside a function instead of at the top of the file. Used in the CLI so that heavy libraries (pandas, xarray) only load when their step actually runs — not when you just want `cli.py --help`. Tradeoff: slightly less readable, but much faster startup. |
